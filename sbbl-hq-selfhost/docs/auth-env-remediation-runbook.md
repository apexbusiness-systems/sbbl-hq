
# SBBL-HQ Auth Remediation Runbook

**Incident:** Unauthorized (401) login errors on `sbbl-hq.icu`  
**Root Cause:** Wrong working directory for `docker compose` — `.env` not found

## Root Cause

`docker compose` was executed from:
```
C:\Users\sinyo\sbbl-hq\sbbl-hq\sbbl-hq-selfhost\sbbl-hq-selfhost\
```

But the `.env` file lives at:
```
C:\Users\sinyo\sbbl-hq\sbbl-hq\sbbl-hq-selfhost\.env
```

Docker Compose reads `.env` **only from its current working directory**. When run from the inner directory, all 50+ environment variables defaulted to blank strings. This caused:

1. `supabase-kong` → crashed on startup (blank `ANON_KEY`, `JWT_SECRET`)
2. `supabase-db` → restarting (blank `POSTGRES_PASSWORD`)
3. All auth API calls → `502 Bad Gateway` from Cloudflare
4. Browser login → `Unauthorized`

Evidence: `powershell-log.md` lines 200–310 show every variable warning as `"variable is not set. Defaulting to a blank string."` Lines 474–478 confirm `supabase-db` and `supabase-kong` both in `Restarting` state.

## Fix — Run in PowerShell (on Docker host)

### Step 1: Navigate to the CORRECT directory

```powershell
cd "C:\Users\sinyo\sbbl-hq\sbbl-hq\sbbl-hq-selfhost"
```

### Step 2: Verify `.env` has the required variables

```powershell
Get-Content .env | Select-String "ANON_KEY|JWT_SECRET|POSTGRES_PASSWORD|SERVICE_ROLE_KEY" | Select-Object -First 8
```

All four must return non-empty values. If `.env` is missing, copy from the inner directory:
```powershell
Copy-Item ".\sbbl-hq-selfhost\.env" ".env"
```

### Step 3: Force-recreate db and kong from the correct directory

```powershell
docker compose up -d --force-recreate db kong
Start-Sleep 30
docker compose ps
```

Expected `docker compose ps` output:
```
supabase-db     ... Up (healthy)
supabase-kong   ... Up (healthy)
```

### Step 4: Validate auth API is live

```powershell
$AnonKey = (Get-Content .env | Where-Object { $_ -match '^ANON_KEY=' }) -replace '^ANON_KEY=',''

Invoke-RestMethod `
  -Uri "http://localhost:8000/auth/v1/token?grant_type=password" `
  -Method POST `
  -Headers @{
    'apikey'         = $AnonKey
    'Authorization'  = "Bearer $AnonKey"
    'Content-Type'   = 'application/json'
  } `
  -Body '{"email":"jrmendozaceo@apexbusiness-systems.com","password":"Apex143!"}'
```

**Expected responses:**
| Response | Meaning |
|----------|---------|
| `{"access_token":"..."}` | ✅ Login successful |
| `{"error":"invalid_grant"}` | ✅ Kong is alive; user account doesn't exist yet (run Step 5) |
| `{"message":"Invalid API key"}` | ❌ Kong still has blank env vars; re-check Step 1 |
| Connection refused / 502 | ❌ Kong or db still crashing; check `docker compose logs kong` |

### Step 5 (if needed): Create user account via service role

Only needed if Step 4 returns `invalid_grant` (account doesn't exist in DB):

```powershell
$ServiceKey = (Get-Content .env | Where-Object { $_ -match '^SERVICE_ROLE_KEY=' }) -replace '^SERVICE_ROLE_KEY=',''

Invoke-RestMethod `
  -Uri "http://localhost:8000/auth/v1/admin/users" `
  -Method POST `
  -Headers @{
    'apikey'        = $ServiceKey
    'Authorization' = "Bearer $ServiceKey"
    'Content-Type'  = 'application/json'
  } `
  -Body '{"email":"jrmendozaceo@apexbusiness-systems.com","password":"Apex143!","email_confirm":true}'
```

Then retry Step 4 — expect `{"access_token":"..."}`.

## Permanent Prevention

Add this guard to any future PowerShell bootstrap scripts:

```powershell
# ALWAYS run docker compose from the directory containing .env
$EnvDir = "C:\Users\sinyo\sbbl-hq\sbbl-hq\sbbl-hq-selfhost"
if (-not (Test-Path (Join-Path $EnvDir ".env"))) {
    throw "FATAL: .env not found at $EnvDir — docker compose will have blank env vars"
}
Set-Location $EnvDir
```

Or use the explicit `--env-file` flag as a fallback:

```powershell

```
